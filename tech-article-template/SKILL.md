# 技术文章写作 Skill

本 Skill 旨在引导 Agent 撰写一篇结构清晰、风格统一、并恰当使用富文本元素的高质量技术文章。最终产物应是一份可直接发布的“准成品”，而非粗糙的初稿。

## 适用场景与典型请求

**何时使用此 Skill：**
当用户的需求涉及撰写结构化的技术类文章时，尤其是当提及以下关键词，应当触发本 Skill：
- “写一篇关于 xxx 的技术文章”
- “帮我撰写一篇技术博客”
- “参考这篇文章的风格，介绍一下 xxx”
- “生成一份产品原理解析文档”

**典型请求示例：**
- “请使用 `aime-skill-creator` Skill 帮我创建一个 skill，按照 `sample-article.lark.md` 这篇技术文章的写作风格整理一个通用的技术文章写作模版，后续其他技术文章可以按照这个 skill 来写。”
- “写一篇关于 'Long-horizon Agent' 的技术介绍文章，风格要像 `sample-article.lark.md` 那样，包含图文和引用。”

## 核心工作流

严格遵循以下步骤，以确保产出质量：

### 步骤一：理解并确认风格

1.  **阅读风格指南**：首先，仔细阅读 `references/style-guide.md` 文档，理解不同写作风格的特点。
2.  **确定文章风格**：根据用户的具体需求确定本次写作的整体基调。如果用户未明确指定，则默认使用“布道师风格”。

### 步骤二：基于模板进行内容创作

1.  **加载文章模板**：读取 `assets/template.lark.md` 文件的全部内容。
2.  **填充模板内容**：严格按照模板提供的结构和每个章节的说明，将用户提供的主题内容填充到相应位置。**不要**随意更改结构或删除模板中的占位符说明。

### 步骤三：运用语言与富文本原则

在填充内容的过程中，需要：

*   **持续参考** `references/style-guide.md` 中的语言和叙事原则，确保文章的语气、视角和读者沟通方式保持一致。
*   **恰当使用** `references/style-guide.md` 中建议的富文本元素（如图片、Callout、Grid 等），以增强文章的可读性和表现力。

### 步骤四：最终校验

1.  **完成初稿**：在完成所有内容的填充和调整后，得到一份完整的文章初稿。
2.  **使用清单检查**：通读 `references/checklist.md`，并根据清单中的每一项对初稿进行逐一核对，确保所有要求均已满足。
3.  **交付产物**：只有在完成所有检查项后，才能将最终的文章交付给用户。

## 资源引用说明

*   `references/style-guide.md`：定义了写作风格、语言原则和富文本用法，是整个写作过程中的核心指导。
*   `references/checklist.md`：用于最终交付前的质量校验，确保成品符合标准。
*   `assets/template.lark.md`：提供了标准的文章结构和内容占位符，是内容创作的起点和骨架。
