# Aiden 排障与升级复验

仅处理原目标被 CLI 入口、版本、随包 Skill 或客户端行为阻塞的情况。保持已固定的 `bytedcli aiden` 入口、身份、空间和 PPE；这个流程不授权新业务写入、切换账号、修改全局配置或提交 issue。

## 先定位，不先重试

1. 记录当前版本、失败命令路径、退出状态、稳定错误码与写入状态；只保留定位需要的裁剪信息，不复制私有 Prompt、完整业务响应或凭证。
2. 读取目标叶子 Help/Schema 和错误恢复指引；参数错误按合同修正，权限不足交用户补授权，远端业务失败按业务恢复处理。受管身份失效时停止，不换账号；升级不能代替这些处理。
3. 若写入已受理、结果未知、读回失败或不能证明请求尚未发出，只做规定的独立读回。未知状态不推导成功、终态或下一步写入；不靠重复提交验证故障。

完成条件：区分已证实原因、未知项、写入是否可能发生。只有仍被客户端问题阻塞时进入下面的升级流程；旧版不支持查新命令时记录该事实，不能据此宣称已是最新版。

## 告知并取得升级授权

向用户说明阻塞证据，以及将执行的主要动作：查询最新版本、通过原入口升级、刷新并重新加载随包 Skill、对原目标安全复验一次。说明会修改本地 Aiden 运行组件和计划中的 Skill 安装目录，可能改变后续调用行为。

得到对这些动作的明确同意后才执行。用户未同意时保留当前安装并报告可选路径；日常查新发现新版不等于获得升级授权。

## 更新、读回、一次复验

1. 查询发行信息；本会话已有成功查新结果可复用，失败或旧版不支持时如实标记未知。`+update` 默认选择 `latest`，版本或通道变更须与用户同意的目标一致。
2. 核对 `+update` 的入口合同：它是实际更新，没有 dry-run。若设置了 `AIDEN_CLI_BINARY`，按返回提示报告覆盖入口，不擅自清除环境或切换安装。
3. 执行一次更新后，用同一入口核对实际生效版本。结果模糊时只读核对；不自动再次更新。
4. 先预览 Skill 安装计划，确认写入目录属于授权范围后安装，用 status 读回并重新加载。无法热重载时说明尚未加载；不能声称已按新 Skill 复验。

```bash
bytedcli aiden self update check --json
# 以下实际更新仅在取得上述授权后执行；JSON 开关放在 aiden 前
bytedcli --json aiden +update
bytedcli aiden --version
bytedcli aiden self skill install --dry-run --json
bytedcli aiden self skill install --json
bytedcli aiden self skill status --json
```

5. 重新读取目标 Help/Schema，只复验原目标一次。读取、dry-run 或合同明确标记 `replay_safe` 的操作可复验；业务写入仅在已证明原失败发生于提交前或可安全重放时重试，否则只读回原目标。

复验成功则报告升级前后版本、Skill 加载状态和原目标结果，到此结束。任一步失败后停止升级循环；既有写入不自动回滚，不通过改变参数、扩大权限或换环境继续试探。

## 仍失败：查重、草稿、单次提交

按随包 Skill 的 `references/troubleshooting-and-reporting.md` 准备最小脱敏报告：目标类别、入口与升级前后版本、Skill 实际加载状态、命令路径、退出状态与错误码、安全最小复现、预期/实际结果及只读恢复结果。不附环境变量全集、绝对路径、私有正文、Token、签名链接或未经确认的资源标识。

- 若故障发生在 bytedcli 安装、参数转发或包装输出层，目标仓库为 `byteapi/bytedcli`；若是 Aiden 命令合同或业务客户端行为，目标为 `ies/aiden-cli`。无法归因时先保留草稿和不确定性，不向多个仓库重复提交。
- 先读取当前 Codebase 客户端 `issue list/create/get` 的 Help，再只读查找目标仓库的同根因开放 issue。列表不完整时标记查重范围；已有相同问题则返回链接，不重复创建。
- 向用户展示目标仓库、查重范围、标题、正文全文和拟用命令，说明将公开的诊断信息及当前身份，另行取得提交授权。升级授权不包含 issue 创建。
- 获准后只提交一次，并用返回 ID/URL 独立读回仓库、标题和正文。模糊结果先只读搜索，不自动再创建；客户端不可用、权限不足或状态未知时交付草稿并明确未提交或未确认。
