# Vimo overseas routing

Read this reference only for CapCut overseas Vimo Web requests. The CLI surface is flat, but
overseas services, sessions, and business objects remain separate from CN.

## 按用户意图选择具体命令

以下命令均加前缀 `bytedcli --site i18n --json vimo`。先使用上下文已明确的业务对象，
再选择动作；UID、TemplateID、task ID 只用于定位对象，不独立决定业务域。

| 用户想知道什么 | 命令 | 返回对象与边界 |
| --- | --- | --- |
| 有哪些分发场景；某场景支持什么模板类型/子类型 | `template distribution-scene list` | `scenes` + `itemTypeMap` 目录，回答后结束，不自动查 Tab |
| 某场景有哪些导航 Tab、标签匹配规则 | `template tab list --nav-type '<nav-type>'` | 导航配置；线上配置显式加 `--env online`，草稿用 `--env draft` |
| 模板列表；某作者发布的模板 | `template list`，按需加 `--uids '<capcut-uid>'` | 模板资源，不能用用户资料替代作者模板列表 |
| 已知 TemplateID 的详情 | `template list --query-mode server --template-ids '<template-id>'` | 对应模板详情；不与数仓筛选混用 |
| 某创作者的资料、已拥有权限/标签、处罚状态 | `creator list --uids '<capcut-uid>'` | 指定创作者记录中的状态，不是权限/标签目录 |
| 有哪些可用创作者权限 key、标签 ID | `creator permission list` / `creator label list` | 动态目录；不能证明某个 UID 已拥有这些权限/标签 |
| 基础用户信息、用户查询页的营销签约状态 | `user list` | 使用 UID、CapCut ID 或一种签约状态查询；不支持无筛选全量用户 |
| 线索类型；线索内容；线索订阅/下发计划 | `creator clue type list` / `creator clue list` / `creator clue plan list` | 类型目录、线索记录、计划记录是三种对象；查询不触发下发 |
| 征稿任务列表、说明、规则 | `creator task list` / `creator task get --task-id '<task-id>'` | 征稿任务；不是成长任务或任务配置模板 |
| 某征稿任务收到的模板、投稿指标 | `creator task submission list --task-id '<task-id>'` | 实际投稿；不使用 `task template list` |
| 某规则的获奖名单 | `creator task reward list --task-id '<task-id>' --rule-id '<rule-id>'` | 奖励记录与发放状态；入选不代表到账 |
| 可复用的任务配置模板 | `creator task template list` | 嵌套任务定义，不是投稿记录或素材模板 |
| 创作者成长任务 | `creator growth-task list --region '<authorized-region>'` | 成长任务配置；地区用 Vimo 授权区域代码 |
| 用户激励的运营活动 | `incentive operation-activity list` | 父运营活动 |
| 复制用户激励运营活动 | `incentive operation-activity copy` | 按 ID 读取父活动配置，预览后创建未上线草稿 |
| 用户激励的活动玩法 | `incentive activity list` | 活动玩法，可按父运营活动筛选 |
| 用户激励中的推荐模板/强插模板配置 | `incentive template list` | 强插配置，不是普通 Feed 推荐结果或推荐算法排名 |

“分发场景”不是 `template list --resource-scene` 的普通剪同款/拍同款筛选，也不是 Tab。
按场景查询导航时，从分发场景目录解析 `navType`，不要把 itemType、Tab ID 或默认 `2000`
当成用户指定的场景。只问场景目录或类型语义时，不需要地区参数或导航查询。

只说“活动”“模板”且上下文无法区分上述对象时，澄清会改变接口的那一项；已明确对象时
直接查询，不重复询问。`creator contract invite` 和 `creator contract terminate` 是写操作，不能用于查询签约状态；
合同号/邀约人等签约管理列表当前未覆盖，不用 `user list` 冒充完整合同管理接口。

## 期间表现与能力缺口

- “近七天表现”“某月收入”“趋势/转化”需要明确对象、日期窗口、时区和指标口径。
  Vimo 可先用于确认对象与状态，随后使用可访问且口径匹配的分析数据源。没有对应数据源
  或权限时，明确列出缺失的期间指标；不要把资源查询成功当作分析完成。
- `template list --start/--end` 筛选模板创建时间，不是曝光、使用或导出的统计时间。
  `UsageAmount` 等字段若无明确窗口契约，不得解释成指定期间增量；创作者 `*_30d`
  指标只能按其固定窗口报告，不能换算成 7 天指标。
- 分发场景目录描述支持范围，Tab 描述导航配置；实际 Feed 命中、排序、曝光和用户可见性
  需要对应运行时或分析证据。当前这些读取命令不提供 Tab Feed 查询。
- 模板查询和写入不自动覆盖目录中的全部 itemType。查询图片、Prompt 等模板类型时，
  先确认当前命令是否支持；不能用模板空列表证明该类型没有资源。
- 保留已知的海外站点、对象和动作。缺少接口或 flag 时说明能力边界，不切到 CN RID
  查询、不把删除改成下线，也不把普通推荐问题改成激励强插配置查询。

## Authentication and network

Overseas `/template/*` and `/user/*` first use a personal ByteCloud JWT for `i18n-tt`.
Managed runtimes can inject `BYTEDCLI_USER_CLOUD_JWT` (or the legacy `AIME_USER_CLOUD_JWT`)
without local `auth login` or a Vimo Cookie. Keep `--site i18n`; the client selects the
`i18n-tt` authentication environment internally, so no extra `--auth-site` is needed.
Request-scoped JWTs take priority, followed by environment JWTs and the shared user
override/session/SDK resolution chain. Explicitly opted-in ZTI follows the shared resolver policy.
A JWT explicitly issued for another region is skipped. Use the intended operator's personal JWT;
the backend still checks identity and business permissions. Never reuse a CN JWT for overseas Vimo.

If no JWT can be acquired, the client falls back to Cookie authentication. Read requests also
fall back after an authentication rejection; writes are never replayed after being sent.
Paths outside `/template/*` and `/user/*` use Cookie authentication directly.

For office-network TikTok SSO/CAS login, the authentication command still uses its concrete auth
site:

```bash
bytedcli --site i18n-tt auth login --session --auto --yes
```

Vimo business commands remain canonical under `--site i18n`.

Managed runtimes may inject the complete browser `Cookie` header value through
`BYTEDCLI_VIMO_COOKIE`. Pass only the value without a `Cookie:` prefix. The value is process-scoped,
host-bound, not persisted, and must never be printed. A rejected injected snapshot does not fall
back to another local identity. Same-origin `Set-Cookie` updates affect only the current process.

`BYTEDCLI_NETWORK_PROFILE=prod` selects the production-network Vimo origin. Production-network
Cookie fallback requires an injected Cookie and fails closed without one; it does not attempt
office-network SSO/CAS. A successful JWT request does not need that Cookie. Protected PPE routing
headers are ignored on that origin.

```bash
printf 'Vimo Cookie: '
IFS= read -rs BYTEDCLI_VIMO_COOKIE
printf '\n'
export BYTEDCLI_VIMO_COOKIE
bytedcli --site i18n --json vimo creator list --page-size 1
BYTEDCLI_NETWORK_PROFILE=prod bytedcli --site i18n --json vimo template list --page-size 1
unset BYTEDCLI_VIMO_COOKIE
```
